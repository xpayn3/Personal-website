# Luka Grčar Portfolio — Project Guide

Static portfolio served from GitHub Pages (repo `xpayn3/Personal-website`, domain `lukagrcar.com`). Plain HTML/CSS/JS, shipped as-is. Read this before changing anything.

## Stack
- No bundler, no framework. One optional generator: `node tools/build-pages.js` (see "Project pages").
- GSAP 3.12.7 + ScrollTrigger + Lenis 1.1.18 from jsDelivr, **desktop only**, loaded by `motion.js`.
- Fonts: IBM Plex Sans / Mono (Google Fonts) for the nav, Work and Lab; the home page, About, Privacy and the project view use the system Helvetica stack.
- Web3Forms for the contact form (browser-side only; their API rejects server-side requests).
- Google Analytics GA4 `G-RXZ65KVMCQ`.

## Admin (`admin.html`)
- Status/editor dashboard at `/admin.html`, live but `noindex, nofollow` (no robots.txt block, so Google can read the noindex; not in the sitemap). Data is `admin-data.js`, regenerated by `node tools/build-admin.js` — re-run and commit it with each push.
- Editing a page commits to `main` through the GitHub API using a fine-grained token the user pastes in (kept in that browser's localStorage). The password gate is client-side only: the page and `admin-data.js` are public files, so keep nothing secret in them.
- **`projects.js`** — the only source of project data. Exposes `window.projects`, `window.gridItems`, `window.COLOR_HEX`, `window.IMG`. Optional story fields per project: `challenge`, `process`, `result` (string or array of paragraphs) add rows to the project view.
- **`project-template.js`** — the project view's markup as one pure function (`ProjectTemplate.html(projects, id, opts)`), used by the browser and by the page generator. Change the project layout here.
- **`overlay.js`** — opens a project in place, the lightbox, the mobile project list, scroll locking. Exposes `window.openProject(id)`, `closeOverlay()`, `openLightbox(idx)`, `closeLightbox()`, `setLightboxItems(items, isLab)`.
- **`motion.js`** — decides whether to load the motion libraries. Everything that uses them checks they exist first.

## Design
- Home / About / Privacy / project view: white page, near-black ink (or the reverse), large tight headlines, labelled two-column rows. Variables `--bg --ink --muted --line --gutter --fade` in `home.css`; dark values under `html[data-theme="dark"]`.
- Work / Lab: a black "gallery wall" (`gallery.css`): square tiles with numbered captions.
- Theme: `index.html` sets `data-theme` before first paint (saved choice in `localStorage['lg-theme']`, else the system setting). `smoke.js` owns the toggle and the nav palette class `body.nav-light`.
- Restrained: no gradients, glows or glass cards. Motion is short and purposeful; respect `prefers-reduced-motion`.

## Home (`smoke.js`, `smoke.css`)
- A fixed full-viewport WebGL2 canvas (`#smoke`) runs a small fluid solver; dragging draws smoke that rises, curls, fades and travels with the page. Falls back to 2D particles without float render targets.
- Text marked `[data-smoke]` (max 2 elements) is rasterised into the canvas while smoke is near it so it can dissolve and reassemble; otherwise it is ordinary DOM text. Desktop only.
- The loop runs only while there is smoke: it stops completely when the air is clear and `wake()` restarts it on a stroke.
- Touch: a resting finger radiates smoke from a thumb-sized circle; sideways drags draw; vertical swipes scroll. While a finger is emitting, `touchmove` is cancelled so the page stays put.
- Tuning panel: open the page with `?controls`. Presets live in `PRESETS`; the first one is the default.

## Project view
- A project is shown **as the page itself**: `body.project-page` hides everything else and the window scrolls. There is no inner scroller. This is what lets phone browsers draw content under their bars. Do not reintroduce a fixed scrolling panel.
- In the site (`index.html`, `grid.html`) a project opens in place and the URL becomes `#project=<id>`; back closes it. Scroll position is restored on close.
- Layout: intro (counter, title, fact sheet) → hero → labelled rows whose labels are sticky and stack into a clickable section index with a progress line → 12-column gallery → next project → colophon. The view turns black once the gallery is on screen (`body.project-dark`).
- Gallery cells have fixed aspect ratios and images lazy-load (`data-src` + IntersectionObserver), so nothing shifts.
- Lightbox: on desktop a picture flies out of its cell and back (transform + clip-path on a stand-in, `.lb-fly`); on touch devices it fades and settles. The thumbnail strip scrubs on touch.
- Scroll lock: desktop pins `<body>`; touch devices use a soft lock (the `touchmove` guard only), because pinning makes phone browsers crop the page. Parallax is frozen while locked.

## Project pages (`work/<id>.html`)
- Generated by `node tools/build-pages.js` from `projects.js`: the same view already in the HTML, with its own title, description, share image and structured data. **Re-run and commit after editing `projects.js`.** It also writes `sitemap.xml`.
- They use `<base href="../">` so the site's relative paths work. `window.PROJECT_PAGE` puts `overlay.js` in standalone mode: Close goes to `grid.html`, Next is an ordinary link, no hash routing.
- Cards, features and next links point at these pages (crawlable); clicks are intercepted to open in place.

## Work page (`script.js`, `gallery.css`)
- Tiles from `window.gridItems` (Lab items are skipped), lazy-loaded; phones use the 300px copies in `Images/mobile/`, falling back to the full image if one is missing.
- Featured blocks (`FEATURED` in `script.js`) are woven in by `placeFeatures()` in whole rows and removed while filtering, searching or in list view.
- Control panel: layout, columns, filters, sort, search.

## Lab page (`lab.js`)
- Every tile is an `<img>` (clips show their `_thumb.webp`); a `<video>` is created only on mouse hover. Opens the shared lightbox with `setLightboxItems(items, true)`.

## Performance rules (phones)
- Nothing may run continuously when idle: no permanent `requestAnimationFrame` loops, no autoplaying video off screen.
- Do not load the motion libraries on touch devices (ScrollTrigger schedules a frame callback forever once loaded).
- On touch devices only the project hero clip plays in the page; other clips stay posters.

## Files and assets
- Images: `Images/<Project>/<file>.webp`; phone copies in `Images/mobile/<Project>/` (300px wide); clip posters as `<name>_thumb.webp` next to the `.webm`.
- Every asset referenced in code must exist. Check with:
  ```bash
  node -e "global.window={};require('./projects.js');const fs=require('fs');for(const p of Object.values(window.projects))for(const s of p.images){const t=s.replace(/\.(webm|mp4)$/,'_thumb.webp');for(const f of [s,t])if(!fs.existsSync(f))console.log('MISSING',f)}"
  ```
- Cache busting: bump the `?v=N` on a script or stylesheet link when you change the file, then re-run the page generator so project pages pick up the new versions.
- `robots.txt`: search engines may crawl `/Images/`; other bots and AI crawlers may not.

## Asset checklist
1. Images: 4096 source → 1024px WebP at quality 85.
2. Videos: MP4 → WebM (VP9), 1080p max, plus a `_thumb.webp` first frame.
3. Phone copy: 300px WebP in `Images/mobile/`.
4. Keep source files. Never delete originals.

## Git workflow
- "push" from the user = commit and push to `main` (which publishes). Never push unless told.
- Never amend, force-push or skip hooks. Destructive git operations need explicit consent.
- Never delete user files without confirmation.

## Known gaps
